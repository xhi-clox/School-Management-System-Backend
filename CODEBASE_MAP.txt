1. PROJECT OVERVIEW
================================================================================
A full-featured school management system ("Academify" / "NexGrad") with three
roles: Admin (dashboard), Teacher (portal), Student (portal). It spans academics,
results/grading, finance, inventory/store, payroll, attendance, class routines,
admissions, promotions, ID cards, report cards, and AI-generated feedback.

Architecture:
- FRONTEND: Next.js 15 (App Router) React 19 app -> "School-Management-system/"
- BACKEND:  Express + Prisma + PostgreSQL REST API -> "School-Management-System-Backend/"
- The frontend calls the backend REST API over HTTP. There is NO Next.js server
  action / route-handler data layer for core features (only /actions.ts for AI).
- IMPORTANT: The backend is MONOLITHIC — nearly all routes/handlers live in a
  single file: School-Management-System-Backend/src/index.ts (~5,475 lines).
  There is no controllers/services folder split.

2. TECHNOLOGY STACK
================================================================================
FRONTEND (School-Management-system/package.json):
- Next.js 15.5.9 (App Router, "next dev --turbopack"), React 19
- Tailwind CSS 3.4 + shadcn/ui (Radix primitives), components.json
- State: React context (AuthContext, LanguageContext), no Redux
- Forms: react-hook-form + zod
- Charts: recharts; Carousel: embla-carousel-react; Motion: framer-motion
- Docs/print: jspdf, html2canvas, jsbarcode, jszip
- AI: Google Genkit (@genkit-ai/google-genai)
- Fonts: Inter / Poppins / Space Grotesk / Hind Siliguri / Playfair Display

BACKEND (School-Management-System-Backend/package.json):
- Node.js >=20, Express 4, TypeScript, ts-node-dev (dev)
- Prisma 6 + PostgreSQL (DATABASE_URL / DIRECT_URL)
- Auth: jsonwebtoken (JWT), bcryptjs
- Validation: zod; Body: express.json 15mb
- Images: cloudinary (base64 -> CDN URL); Security: helmet; Logging: morgan
- CORS allows all origins (config lists Vercel prod + localhost + env CORS_ORIGINS)

9. BUSINESS LOGIC (actual implementations — read these before changing behavior)
================================================================================
A) RESULT / GRADE CALCULATION  (src/index.ts POST /results/bulk, lines 1423-1549)
   Input: per-student { written, mcq, practical }
   - totalMarks = written + mcq + practical
   - Highest marks computed across this batch + existing results for (exam,subject)
   - Pass/fail: isFail if (written < writtenPass) OR (mcq>0 && mcq<mcqPass) OR (total < totalPass)
     (threshol/grade from GradingSystem rows for the exam's ExamType)
   - fullMarks resolved from ExamSchedule for the student's class (default 100)
   - percent = totalMarks/fullMarks*100; grade from GradingSystem band (or 'F' on fail)
   - Upserts Result rows; then updateMany to sync highestMarks for all rows of (exam,subject)
   NOTE: teacher /teacher/marks (4912) saves pre-computed total/grade/gp directly (different path).

B) EXAM REPORT / OVERALL GRADE & GPA  (src/index.ts buildExamReport 1553-1628 + overview 1655)
   - Per student: sum totalMarks & fullMarks; gpa = (sum gp)/(#gp); percentage = total/full*100
   - Fail grades set derived from GradingSystem status='FAIL' (default 'F'); if any FAIL grade -> overall grade 'F'
   - subjectStatsForReport (1630): average % and pass rate per subject
   - rankStudents (1649): sort by gpa desc, then percentage desc, then name
   - Overview computes pass rate, class performance, top-10, at-risk (failed or gpa<2.0), weakest subjects.

C) MONTHLY TUITION GENERATION  (POST /tuition/generate-monthly, 2453)
   For each Active student: skip if a 'tuition' invoice already exists for billingMonth.
   Amount priority: (1) matching StudentFeeAssignment (customAmount ?? feeStructure.amount) minus
   discountPercent; (2) class AdmissionPackage tuition feeItem. If <=0 skip.
   Optional prorate: if admissionDate is in target month, amount * remainingDays/totalDays.
   Creates Invoice type='tuition' due on dueDay; invoice item "Monthly Tuition - YYYY-MM".

D) PAYMENT LOGIC + INVOICE STATUS  (POST /payments 3265)
   newPaid = inv.paid + amount; status = paid if newPaid>=total else partial.
   Creates Payment row + increments invoice (also likely creates LedgerEntry income — verify).
   /invoices/from-package and /invoices/simple build invoices (+optional initial payment).

E) ADMISSION  (POST /students/admission 3065)
   - Requires packageId; copies pkg class name/section; admission number auto "ADM-00000" or manual (regex 1-5 digits -> ADM-xxxxx); rejects duplicate roll in class/section.
   - Creates Student (status pending_payment), upserts Guardian, creates Invoice type=admission
     with all package fee items; all in one $transaction.

F) PROMOTION / GRADUATE / RETAIN  (POST /students/promote 943)
   - Only Active students; promote re-assigns roll per destination class/section (max+1) and
     writes a StudentAcademicRecord (status Promoted). Graduate sets status and writes record.
     Retain bumps year and writes Retained record. All in one transaction.

G) ATTENDANCE MATRIX  (GET /attendance/matrix 2575)
   Month grid, per-student records mapped to P/A/L/LV letters, daily totals, percentage of days present.

H) STORE PROFIT  (GET /store/reports/profit 2873)
   Aggregates sales/purchases per product: revenue, sold qty, profit (likely revenue - cost). Read source.

I) FINANCE SUMMARY  (GET /finance/reports/summary 3582)
   totalIncome/totalExpense/netProfit from LedgerEntry; grouped by category.

J) AUTH (INSECURE/SIMPLIFIED)
   - Admin: password must equal 'fresh_password_2026' OR match bcrypt hash (only for admins w/ bcrypt)
   - Teacher: password may equal employeeId, email prefix, or ANY of 'password'/'test'/'123456'
     (hardcoded test passwords — do NOT treat as secure)
   - Student: via StudentLogin.password plaintext compare, or fallback accepts ANY password for a
     student matched by email/admissionNo (very insecure)
   - JWT secret falls back to 'fallback-secret'; 7-day expiry.

K) INSTITUTE PROFILE
   /institute requires ?email; auto-creates default row on GET if missing; upserts on POST.

15. ARCHITECTURAL RULES (observed patterns — follow them)
================================================================================
Backend:
- Monolithic: routes + controllers + services all inline in src/index.ts. When adding features,
  append handlers there (or consider extracting, but don't break existing).
- Validation with zod schemas inside each handler (safeParse -> 400 on fail).
- Prisma is the sole DB access layer (PrismaClient). Money fields are Prisma.Decimal; the app
  serializes Decimal to numbers globally (see top of src/index.ts).
- Auth: authMiddleware (JWT) then checkRole([...]) for protected routes.
- Images: base64 photos converted to Cloudinary URLs by a global body middleware before handlers.
Frontend:
- All API calls go through src/lib/api.ts (admin/teacher) or src/lib/student-api.ts (student portal).
- Data fetching is client-side ('use client' + useEffect/useState) toward the REST API.
- UI components via src/components/ui/* (shadcn). Feature pages import from @/components/feature.
- Auth via AuthContext + localStorage token/user.
- i18n via LanguageContext (en/bn). Some pages still have hardcoded strings.
