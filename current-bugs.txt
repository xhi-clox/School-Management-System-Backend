🐛 BUGS & INCONSISTENCIES
Attendance Module
1. Status Inconsistency (index.ts:3747, 5915)
- Default status is hardcoded as 'Present' (capital P) in some places
- Database stores variations: 'present', 'Present', 'PRESENT', 'Absent', 'Late', 'Leave'
- Normalization logic exists but is inconsistent across endpoints
2. Date Handling Issues (index.ts:302-304, 3737)
- Attendance dates use UTC midnight for storage but local time for querying
- Mixed date handling between attendance (UTC) and ledger queries (local time)
- Potential timezone bugs when fetching "today's" attendance
3. Teacher Attendance Permission Check (index.ts:5875-5878)
- Uses classId string comparison but the permission system may return class objects
- No validation if teacherAllowedClassIds() returns empty set
4. Duplicate Attendance Records Risk (index.ts:4346-4350)
- Upsert based on studentId_date composite key
- No transaction isolation level specified - concurrent requests could cause race conditions
Exams & Grades Module
5. Exam Attendance Missing Validation (index.ts:1554-1603)
- No check if exam schedule actually exists for the date/subject/class combination
- Could save attendance for non-existent exam schedules
6. Grade Calculation Logic Flaw (index.ts:1752-1771)
- Pass/fail logic checks m.mcq > 0 && m.mcq < mPass 
- If MCQ marks are exactly 0, student passes even if MCQ was mandatory
- Inconsistent handling of optional vs mandatory components
7. Highest Marks Calculation Bug (index.ts:1733-1739, 1814-1817)
- Highest marks calculated from current batch + existing results
- Then updates ALL results with the same highestMarks
- This overwrites individual subject-wise highest marks with global highest
- Bug: Should be per subject-class combination, not global
8. Full Marks Fallback Chain (index.ts:1759-1762)
- Falls back to schedules[0].fullMarks if student's class schedule not found
- Then defaults to 100
- Could assign wrong full marks if schedule order changes
9. Exam Type Default Issue (schema.prisma:501)
- typeId has @default("") which creates invalid foreign key relationships
- Should be required or nullable, not empty string
Results Module
10. Result Status Transition Logic (index.ts:2183)
- Publishing checks for Finalized, Draft, or Verification status
- But ALLOWED_STATUS_TRANSITIONS doesn't allow direct Draft → Published (line 2088)
- Inconsistency: endpoint allows transitions that the validation function blocks
11. GPA Calculation Without Subject Weights (index.ts:1870)
- GPA calculated as simple average: gpSum / gpCount
- Doesn't account for subject credit hours or weights
- All subjects treated equally regardless of importance
12. Weighted Academic Score Missing Exam Check (index.ts:2103-2126)
- Function silently skips exams that fail to build reports
- No logging or error indication
- Could produce incorrect weighted scores without warning
13. Validation Missing Duplicate Check (index.ts:2407)
- Reports noDuplicateResults: true hardcoded
- Never actually checks for duplicate Result records
- Composite unique key exists but validation doesn't verify it
14. Percentage Calculation Division by Zero (index.ts:1871)
- (totalMarks / fullMarks) * 100
- If fullMarks is 0, produces Infinity or NaN
- Could crash grade lookup
15. Result Lifecycle Status Mismatch (schema.prisma:506, 565)
- Exam has status field for lifecycle (Draft/Published)
- Result also has status field (Draft/Verification/Finalized/Published)
- Bug: Results updated individually but exam status is global
- Exam can be "Published" while individual Result records remain "Draft"
16. Missing Transaction Isolation (index.ts:1748-1810)
- Bulk result upsert in transaction
- Followed by separate updateMany for highestMarks (line 1814)
- Second query outside transaction - could cause partial updates on failure
Cross-Module Issues
17. Exam Attendance vs Regular Attendance Duplication
- Two separate systems: Attendance and ExamAttendance
- No synchronization between them
- Student marked present in regular attendance but absent in exam attendance
18. No Academic Year Validation (index.ts:1401, 1929)
- academicYear stored as string, no validation
- Queries depend on exact string match
- Typos like "2024-25" vs "2024-2025" break reports
19. Teacher Permission Scope Inconsistency (index.ts:5856-5981)
- Teacher attendance endpoints check teacherAllowedClassIds()
- Admin attendance endpoints have no such restrictions
- Teachers could potentially access through admin routes if auth is weak
